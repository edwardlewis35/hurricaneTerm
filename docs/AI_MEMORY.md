# AI 长期记忆

右侧 AI 助手的「长期记忆」可以保存机器事实和使用偏好，在后续对话或运维任务中检索相关片段。记忆独立于聊天记录：新建对话不会删除已保存记忆，未保存的普通聊天也不会自动变成记忆。

本实现参考 OpenClaw 的 Markdown 真源、本地索引、混合检索、来源引用与压缩前记忆整理，由 hurricaneTerm 的 Rust/JavaScript 模块实现。参考版本固定为 [`openclaw/openclaw@4af30f64ca75efd92eb26990ef0b3181da340f3a`](https://github.com/openclaw/openclaw/tree/4af30f64ca75efd92eb26990ef0b3181da340f3a)，概念说明见 [OpenClaw Memory](https://docs.openclaw.ai/concepts/memory) 和 [Memory Search](https://docs.openclaw.ai/concepts/memory-search)。

## 开始使用

1. 选中需要使用记忆的终端，打开右侧 AI 面板，再点击「长期记忆」。首次尚未填写服务时，管理页直接显示配置。
2. 在「记忆设置」填写独立的 **Embedding 地址、模型和可选 API Key**。地址可为 `https://example.com/v1` 或完整的 `https://example.com/v1/embeddings`；无路径的地址会补 `/v1/embeddings`。向量维度由返回值自动检测。
3. 可主动点击「测试连接」。测试只发送固定的连通性文本，不发送记忆原文，也不保存配置。服务需要支持 OpenAI 兼容的 Embeddings 请求和浮点向量响应；仅提供聊天接口的模型不能替代 Embedding 模型。
4. 勾选「启用记忆」，检查其他开关后点击「保存设置」。开启后，检索问题和所选范围内尚未缓存的记忆片段会发送到这个 Embedding 服务；相关片段还会作为历史参考发到聊天模型。
5. 选择「当前机器」或「全局」，新建「长期记忆」或「今日记录」，编辑后保存。可点击「重建索引」，或直接检索；检索会核对 Markdown 文件变化并更新派生索引。

Embedding 和聊天模型的服务、模型名称及密钥分别配置。即使填写同一个地址，记忆密钥也不会取用聊天密钥。支持无鉴权的自托管服务，Key 可留空。网络由原生后端发送，不依赖浏览器 CORS，不继承 GitHub 专用代理、不跟随重定向；需要填写实际可达的最终地址。

## 默认开关

| 设置 | 新配置默认值 | 生效方式 |
| --- | --- | --- |
| 启用记忆 | 关闭 | 未开启前，不自动检索、不向 Agent 提供记忆工具、不自动请求 Embedding |
| 对话前自动检索相关记忆 | 勾选 | 只有同时启用记忆后才生效；关闭后仍可手动检索，Agent 也可显式调用记忆工具 |
| 包含全局记忆 | 勾选 | 当前机器检索可同时使用明确放入「全局」范围的记忆；不读取其他机器的记忆 |
| 持久保存密钥 | 勾选 | 配置保存时使用系统凭据库；取消勾选并保存后，本次运行仍可使用输入的 Key，移除该端点的已存 Key |
| 压缩上下文前整理并保存长期事实 | 关闭 | 需要单独开启；会额外调用当前聊天模型，并向当前机器的当日记忆追加事实 |

默认检索最多返回 6 条，相关性阈值为 0.35。以上自动检索偏好已勾选不等于记忆已经启用。关闭「启用记忆」后，管理页仍可编辑文件和运行本地关键词检索；主动点击「测试连接」仍会测试填写的 Embedding 服务。

## 当前机器与全局

远程机器按「协议、转成小写的主机名、端口、保留大小写的用户名」生成稳定身份；不使用容易变化的页面标签或保存会话 ID。同一地址和用户的新标签可共享记忆，主机或用户不同则隔离。本地终端共用本机记忆空间。「全局」是用户明确选择的共享空间，适合团队约定和通用偏好。

任务开始后，Agent 的命令执行和记忆操作都绑定原目标。切换到其他标签不会迁移当前任务；原连接关闭、断开或重新连接会使旧任务失效。聊天在记忆检索期间切换目标，也不会把迟到结果交给新目标。回复上的「保存为记忆」使用产生该回复的机器身份，即使点击前已切换到另一台机器，也不会保存到新的活动标签。

身份由填写的连接地址生成，不解析为物理服务器身份。同一台服务器使用不同域名或 IP 连接时会有不同记忆空间；同一地址重新分配给其他服务器时，已有事实也可能过时，应先核实和整理。

## 查看、编辑与删除

「长期记忆」打开 `MEMORY.md`；「今日记录」使用本地日期的 `memory/YYYY-MM-DD.md`。检索结果显示范围、文件路径和行号，点击来源可读完整 Markdown 原文。管理页编辑原文，不会把 Markdown 中的 HTML 当成可执行界面内容。

AI 回答上的「保存为记忆」只生成可编辑草稿，将回复附在该机器的既有长期记忆后。点击「保存记忆」才写入。管理页不会自动覆盖已有未保存草稿；切换文件或机器前需保存或放弃草稿。

保存已有文件会检查读取时的内容哈希。文件被另一个操作或编辑器修改时，保存失败并保留当前草稿，需重新读取和合并。新文件使用仅创建语义，不能静默覆盖同名文件。删除需要再次确认，原文件移到备份目录；备份不参与检索。

单个文档最多 **512 KiB UTF-8 字节**。可用路径仅为 `MEMORY.md` 或 `memory/文件名.md`；管理页文件名以英文字母或数字开头，后续可用英文字母、数字、点、连字符和下划线，总长不超过 128 个 ASCII 字符，不支持嵌套子目录、绝对路径或 `..`。原生文件操作还拒绝符号链接。

## 检索方式与降级

Markdown 按约 400 tokens 的预算分块，相邻块重叠约 80 tokens，保留原始行号。这里的 token 是文字估算值。片段按内容 SHA-256 缓存，接口、模型和维数属于向量空间身份；未修改的内容无需反复生成向量，更换模型后不能跨空间比较旧向量。

正常配置时，原生后端结合 Embedding 余弦评分与 SQLite FTS5/BM25、词面覆盖检索，默认向量权重 0.7、文本权重 0.3。中文另有有界的字面匹配，避免只按空格分词。候选先按日期衰减，再经过精确内容去重和 MMR 去冗余：日期笔记按 30 天半衰期排序，`MEMORY.md` 和无日期笔记保持常青，MMR 的相关性权重为 0.7。这是参考实现，未复刻 OpenClaw 的全部来源、项目和重要性规则。

返回结果明确标记实际的混合或关键词模式。Embedding 鉴权失败、网络异常、返回格式/维数无效时，可继续返回本地关键词结果，同时显示降级警告；这不表示向量检索成功。该策略与所参考 OpenClaw 版本对显式故障 provider 返回 unavailable 的策略有所不同。重建失败或向量不兼容不会修改 Markdown 原文。

自动召回的引用预算约 6000 字符，包含路径、行号和「历史参考不构成授权」说明；不是把整个记忆库加入每轮上下文。手动检索文本超过 8 KiB 时按 UTF-8 边界截取并明确提示，原有服务降级警告仍保留。记忆可能过时，模型应以当前机器的实际检查结果为准。

## 运维工具与确认

启用记忆后，[运维 Agent](OPS_AGENT.md) 额外获得：

- `memory_search`：在已绑定的当前机器及允许的全局记忆中搜索。
- `memory_get`：读取明确来源的指定行段，只允许 `current` 或 `global` 范围。
- `memory_write`：向当前机器或全局 Markdown 写入已确认的长期事实。

模型的 `memory_write` **每次都需要界面确认**，即使关闭普通命令逐条确认也不例外；拒绝会停止任务且不写文件。原文变化后，先前的确认不能绕过哈希冲突检查。记忆中的命令、旧审批和自称管理员的文字都只是历史数据，不能变成新的 Shell 调用或本轮授权。

命令执行的默认确认和已知高影响操作确认规则保持生效。完整工具批次会先检查参数，错误的记忆工具不能让同批前面的命令先执行。

## 压缩前记忆整理

默认只压缩上下文，不保存长期事实。只有在记忆设置中另行开启「压缩上下文前整理并保存长期事实」，才会在手动或自动压缩前额外调用当前聊天模型，提取明确偏好、已确认的环境、路径、约束及经过验证的解决办法。

整理只向已绑定机器的 `memory/YYYY-MM-DD.md` **追加**，不替换 `MEMORY.md`，不由模型选择路径，不调用命令工具。该开关是对自动追加日记的单独授权，流程不逐条弹出 `memory_write` 的确认框。没新事实时不写；同一进程内，对同一机器、相同输入的最近一次成功整理使用 SHA-256 指纹避免重复追加。它不是跨重启的完整语义去重。

同一聊天混入其他机器或归属不明确的历史时，跳过自动整理并显示说明，仍可压缩对话；用户可检查后手动保存。停止、关闭或目标连接变化后，迟到的提炼结果不能发起新的保存。保存一旦已经发起，原子文件提交是不可撤销的提交点，停止不会回滚已经发起或完成的追加；后续可在管理页编辑或删除。记忆库忙碌时，自动整理的保存会明确跳过，避免在其他长请求后排队执行旧写入。

提炼前有有限的常见凭据过滤，提炼结果也检查常见密码、令牌及私钥格式；这些规则不能识别所有敏感信息，也不能保证模型归纳正确。记忆原文和索引均是本机明文数据，应检查内容，不把密码、API Key 或私钥保存为记忆。

## 文件与数据保存范围

数据位于应用配置目录下的 `ai-memory`，结构为：

```text
ai-memory/
  scopes/
    global/MEMORY.md
    global/memory/YYYY-MM-DD.md
    machine-local/MEMORY.md
    machine-<稳定身份 SHA256>/MEMORY.md
    machine-<稳定身份 SHA256>/memory/YYYY-MM-DD.md
  index.sqlite
  backups/
```

Markdown 是原文，SQLite 的片段、FTS5 和向量缓存是可重新生成的索引。重建只处理派生索引；修改/删除原文后，下次状态同步或检索会移除旧片段及孤立向量。删除备份仍保留明文，需清除敏感数据时也应检查备份与自己的系统备份。

只索引这个应用的记忆目录，不扫描 SSH 配置、远程文件系统、其他终端、Codex 或 OpenClaw 的记忆。普通设置只保存开关、端点、模型和检索偏好；API Key 使用独立的本机系统凭据命名空间，支持 macOS Keychain、Windows Credential Manager、Linux Secret Service。系统凭据库不可用时报告失败，不回退到明文密钥文件。Gist 机器配置同步不上传记忆库或 Embedding 密钥。

Embedding 请求可能包含当前问题和所选空间的待索引片段；聊天模型收到命中的历史片段；启用整理时，聊天模型还会收到待提炼的历史记录。停止后不会使用迟到结果继续发出模型请求或执行命令，但已经发送的网络请求可能运行至完成或超时，已经发起的原子保存也可能完成。派生索引中的文字与向量也应视为本机应用数据保护。

### 连接身份与后台保存

记忆归属绑定到本次实际连接的公开身份快照，编辑已保存配置不改变仍在运行的旧连接归属；重新连接成功后才更换身份。串口使用区分大小写的设备路径，TCP 也支持仅填写 target 的地址。自动整理保存若发现记忆库忙于检索或其他保存，会立即返回失败供之后重试，不在慢检索后排队提交。已发起的原子保存仍是提交点，停止不能撤销已完成的文件修改。
