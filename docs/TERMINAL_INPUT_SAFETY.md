# 终端输入安全审计（v0.11.3）

## 自动密码与回车的原因

旧 SSH 实现在 USERAUTH 成功后，仍用默认的 `AutoLoginExpect` 监视 shell 输出。遇到 login/username 提示时发送保存的用户名和回车；遇到 Password/sudo 密码提示时发送保存的 SSH 密码和回车。这个过程持续到会话结束，没有用户启用条件。

因此 `sudo passwd user` 的当前密码、新密码和确认密码提示可能触发自动输入。它既可能泄漏登录密码，也可能把该密码提交为新密码。这是产品输入处理缺陷。是否已经改变某台机器的密码，不能从客户端代码判断，应由机器所有者检查相应账号；回归没有运行真实 passwd 或修改账号。

修复删除整个认证后提示词匹配及自动发送分支。SSH 密码和 keyboard-interactive 认证仍在 USERAUTH 阶段处理；进入 shell 前释放密码变量，shell 输出不能调用凭据路径。保留未调用的通用匹配器源码不代表它仍连接到 SSH 输入。

真实回环 SSH 对端测试在旧版失败，确认收到保存密码及回车；同一测试在修复版通过。覆盖普通密码、sudo、当前/新/确认密码、login/username 提示，完整及两字节分片，stdout 与 stderr。SSH 密码认证和 keyboard-interactive 分别建立真实连接，随后验证手动输入。

## 丢包、顺序与失败

[TCP 提供可靠、有序字节流及重传](https://www.rfc-editor.org/rfc/rfc9293.html#section-2.2)，[SSH 通道另有窗口流控](https://www.rfc-editor.org/rfc/rfc4254.html#section-5.2)。网络丢包不需要客户端盲发相同按键；部分写入或连接失效后，重放不能确认的命令可能重复执行。

应用原有两个问题：orderWrites 是空占位，多个前端写入可并发进入原生桥；写入错误被转成 false，输入回调没有呈现错误。现在每个连接世代使用一个 FIFO，同队列串行处理文本和二进制输入，前一次原生调用返回后才发下一次；不同终端独立工作。

- 写入失败或缓冲超限时暂停队列，显示不包含输入内容和后台错误原文的提示。
- 普通新输入不能绕过暂停；不自动重试可能已部分送达的内容。
- Ctrl+C 清除尚未发送的内容及排队回车，在已有调用返回后尝试一次中断；失败会再次暂停。应检查远端状态后再操作。
- 关闭、断线、重连让旧队列失效；即使复用原生 ID，也不能向新世代重放旧输入。
- 前端缓冲使用 1 MiB 保守字节预算，文本按 UTF-16 长度三倍估算，超限明确拒绝。

原生调用成功仅表示本地 writer 接受输入；SSH writer 当前把数据放入本地发送通道。这不是“远端命令已执行”的回执，不能跨断线恢复输入。原生 SSH 发送通道仍无界，后续可增加背压；本次没有混淆本地接受、TCP 收到和 shell 执行。

Linux 私有用户/网络命名空间中，对同一生产 SSH 实现加入 20ms±5ms 延迟、3% 丢包，统计实际丢弃 23 包，两个认证路径的提示及手动输入测试均通过。另覆盖对端暂停读取、512 帧分片突发，检查顺序与重复。未修改宿主网络。这是指定条件下的实测，不代表任意网络或断线后输入都能恢复。

## 同类输入路径修复

| 路径 | 原问题 | 修复约束 |
| --- | --- | --- |
| 密码与大纲 | 原始按键在 Enter 时进入大纲，可能保存无回显密码 | 仅记录已出现在公开回显单元中的内容；复杂行编辑宁可跳过 |
| Tab | 本机候选替换远端输入，不适用于密码提示、远端路径或 TUI | 原样传给 xterm 和远端 shell，不调用客户端补全 |
| 粘贴 | 部分入口绕过 bracketed paste、换行规范和传输占用检查 | 工具栏、快捷键、中键、右键统一调用 xterm.paste，不额外添加回车 |
| 异步剪贴板 | 返回后取活动标签，可能发往另一机器 | 读取前固定标签、原生 ID 和世代；切换不改目标，关闭/重连则取消 |
| 快捷键 | 应用快捷键与终端键混杂，部分应用操作无法触发 | 活终端保留 Ctrl 字母键及 F2/F3/F11；应用用 Ctrl+Shift 或 macOS ⌘，一次执行 |
| 快捷键焦点转移 | 面板接收 keyup 后，终端残留按键标记可能吞下回到终端后的首个大写字母 | 新的非重复物理 keydown 清掉同键旧标记；持续按住的 repeat 仍被消费，真实面板/搜索焦点迁移纳入回归 |
| 输入法 | 提前吞 229 绕过 xterm 对数字/标点的差异兜底 | 活终端的 229 交给 CompositionHelper；候选确认 Enter 不提交命令 |
| 8 位鼠标报告 | 未订阅 onBinary，可能丢失报告 | write_binary 保留字节，共用文本 FIFO；不广播鼠标坐标 |
| 输出触发器 | send 后 UI 日志异常可能走备用处理再次发送 | 仅原生调用本身失败时选备用处理，不因 UI 错误重放 |
| XYZMODEM 排他 | IPC 取消先释放租约，阻塞 writer 仍在执行 | 租约移入 blocking 闭包，实际写入结束才释放 |

明确配置的发送触发器、显式同步输入、发送窗格和获授权的 AI 命令仍可产生输入。它们是独立的用户功能；默认同步关闭。本次移除的是未经用户配置、仅凭密码提示就发送凭据的行为。检查现有触发器时也应核对自身配置。

## 回归与范围

`npm run test:terminal-input-safety` 使用真实 xterm DOM/键盘、composition、paste、binary 事件及生产 core/term/ui。桥接、剪贴板和无关面板受控，不连接用户机器。覆盖普通字符、大小写、单个 Enter、Tab、方向/编辑键、Ctrl+C/D/Z/U/W/R/T/B/F/M、功能键、Unicode/emoji、标准和 229 输入法、无回显密码、公开大纲、五种粘贴入口、目标竞态、同步/传输占用、慢回执、失败/超限提示、取消与世代隔离、触发器防重复发送。

`cargo test --locked --manifest-path src-tauri/Cargo.toml ssh_live::shell_input_safety_tests` 使用真实回环 SSH 客户端和对端，检验两种认证、认证后零自动输入、控制序列、UTF-8 和任意二进制字节。既有会话失败、resize、关闭、SFTP、XYZMODEM 和 AI 回归继续运行；Linux 另测 lrzsz 独立对端，macOS 另测真实 PTY 关闭。

三平台生产 Tauri 编译、实际计数及安装包校验见发布审计。开发阶段隔离 Rust 接口适配测试不替代 Tauri 宏、系统 WebView 和完整链接检查。

尚未覆盖：解锁后的 macOS 原生 GUI 输入法及真实交互编辑器手工验收、真实串口硬件、用户专有 SSH 跳板/网络组合、任意长期恶劣网络压力。测试通过不能作为“所有终端功能永远无故障”的承诺。
