# AI 运维 Agent

右侧 AI 面板现在有「对话」和「运维 Agent」两种模式。对话是默认模式，生成的命令需要你手动插入并执行。明确切换到运维模式、输入任务并点击「运行任务」后，Agent 可以在所选机器上执行命令、读取执行结果，再决定下一步。

## 使用

1. 连接要操作的 SSH 机器，或打开本地终端，选中对应标签或分屏。
2. 在右侧 AI 配置中填写自定义服务地址、模型和可选 API Key。端点须兼容 OpenAI Chat Completions，并支持原生 function/tool calling；仅支持普通文本聊天的模型不能执行任务。
3. 切换到「运维 Agent」，检查面板里的目标机器名称。描述明确的目标和限制，例如「排查这个 Nginx 服务返回 502 的原因，先检查日志和上游连接，保留现有配置，只修复这个问题并验证」。
4. 点击「运行任务」。默认每条命令先请求确认；可关闭「每条命令执行前确认」，让普通诊断和任务范围内的可恢复操作继续执行。每个步骤显示执行目的、实际命令、输出和退出码，最终答复显示在步骤记录后面。
5. 面板请求确认时，点击「允许本次执行」只批准完整展示的这一条命令；点击「以后全部执行」会执行当前命令，并授权本任务后续所有命令（含已知高影响操作）连续执行；点击「拒绝并停止」结束任务。全部执行授权仅限当前任务与原目标，不修改全局设置，不带入新任务或恢复任务。

任务在开始时锁定具体终端、原生连接 ID 和连接代次。切换标签页不会把任务转移到其他机器；关闭标签、断线或重新连接会停止旧任务。重新连接后需要明确启动新任务。当前支持 SSH 和本地终端，Telnet、TCP、串口暂不提供运维执行。

## 长期记忆工具

在 AI 顶部「长期记忆」中可独立配置 Embedding 服务并启用[记忆系统](AI_MEMORY.md)。默认关闭，不影响原有无记忆的运维任务。开启后，任务开始可先检索已绑定机器和允许的全局记忆；模型还可调用 `memory_search` 搜索、`memory_get` 读取原文行段、`memory_write` 保存事实。关闭自动检索后，这些已启用的显式工具仍可使用。

模型调用 `memory_write` 每次都必须经过界面确认，即使普通命令确认已经关闭。拒绝会停止任务，外部文件变化仍会触发哈希冲突。记忆中的命令或旧批准不能替代本轮 `run_command` 和确认流程；结果按历史参考展示，带有文件与行号，Embedding 故障时明确显示关键词降级。任务与记忆始终绑定原机器，完成后切换标签再保存回复也使用原目标。

「压缩上下文前整理并保存长期事实」为单独的默认关闭选项；开启后，压缩前可由聊天模型提炼本任务已确认的事实，向该机器当日 Markdown 日记追加，不逐条弹出模型 `memory_write` 的确认框。它不保存整份任务日志或审批权限，停止及连接失效后不会用迟到提炼结果发起新的保存；已发起的原子文件提交不能通过停止撤销，之后可在管理页编辑或删除。跨机混合或归属不明的聊天历史跳过自动整理。记忆原文与索引是本机明文，Gist 机器同步不上传它们。

## 它如何决定下一步

这是同一个模型驱动的 ReAct 工具循环，带有根据真实结果修正和验证的步骤：

```text
用户目标 → 模型选择 run_command → 独立执行通道
                                ↓
最终总结 ← 模型判断是否完成 ← stdout / stderr / 退出码 / 超时状态
                  └─ 未完成：提出下一条命令，并继续验证
```

例如某个检查返回退出码 1，模型会接收到这次执行的结构化结果，然后可以提出修正后的检查或配置命令，最后再验证。没有工具调用的普通回答结束任务。没有固定的思考轮数、命令总数或任务总时长，Agent 可以持续工作到完成或用户停止；这不保证模型会自行判断正确。它使用原生工具调用结构，不把模型回答里的代码块、JSON 片段或文字猜测为命令，不展示私密思维链。

运维提示要求先确认系统、身份和环境，先诊断再做最小变更，并以命令输出验证结果。执行失败不等于任务完成，输出被截断也不代表看到了全部证据；模型应改用过滤、分页或更小范围的检查。上述要求是模型行为约束，最终判断仍可能出错，应结合步骤记录检查结论。

## 执行方式与权限

SSH 命令在已有认证连接上创建独立的 exec 通道。本地命令由独立进程执行。Agent 不向你正在操作的交互 Shell 注入按键或命令，不依靠提示符、特殊标记或定时等待猜测命令是否结束。结构化结果包含 `stdout`、`stderr`、`exitCode`、`signal`、`durationMs`、`timedOut`、`cancelled`、`truncated` 和请求工作目录。

每条命令都是独立执行：不会继承你在终端里手动运行的 `cd`、`export`、别名、虚拟环境，也不会继承上一次工具调用的 Shell 状态。需要工作目录时使用工具的 `cwd`；需要环境变量时在该次命令里明确设置。省略 `cwd` 时，本地以创建标签时应用的工作目录为初始目录，SSH 使用服务器 exec 通道的默认目录，通常为用户主目录；登录配置仍可能影响最终目录，定位问题时应显式检查或指定目录。任务不会改变交互终端的当前目录。macOS/Linux 本地使用非交互的 `/bin/sh`，Windows 本地使用非交互 PowerShell；远端命令需要服务器支持常见的 POSIX Shell，非 POSIX SSH 服务端不在本版兼容范围内。

执行使用当前连接用户的系统权限，不会创建额外的系统权限边界。需要提权时必须用 `sudo -n`；没有免密权限则返回错误，不弹出密码输入，也不把密码交给模型。输入从空设备读取，不适合交互编辑器、需要应答的安装向导或持续前台运行的程序。启动或调整服务应通过明确的服务管理命令完成。

命令和结果会作为标记清楚的文本回显到原目标终端，同时保留在右侧步骤记录里。回显走终端输出队列，移除 ANSI/OSC 控制序列，禁用回显的自动命令触发器，也不会进入同步输入或广播路径。它是执行记录，和在交互 Shell 中键入并运行命令的历史不同。

任务结束后，若当前仍选中原目标且连接未变，恢复终端输入焦点，不需要按回车。程序不会代替你发送回车，也不会自动提交交互 Shell 中已经输入的草稿。若你切换到了其他机器，则不把焦点拉回原目标。

## 持续运行与上下文

面板显示当前上下文的估算 token 数与配置容量；估算不是服务端计费数据。启用自动压缩后，接近容量时通过所选模型摘要较早的命令与结果，保留原始运维指令、当前目标以及最近的完整工具调用/结果组。摘要只作为参考，不能替代当前任务的授权或新的执行确认。初次运行时较长的先前对话也可以先摘要，尚未执行的当前任务保持完整。

摘要失败时明确停止，保留原记录，不静默删除证据；摘要后保留内容仍超出容量时也会停止并提示缩小单次输出或附件。关闭自动压缩时，到达上下文容量会停止。压缩不修改界面中的既有步骤记录。相同命令连续三次失败且结果相同会停止，避免无进展地重复变更；成功轮询与不同的修正步骤不会触发这一保护。

## 单次请求与执行限制

| 项目 | 上限 |
| --- | --- |
| 一个任务的模型轮次、命令总数、总时长 | 无固定上限；可随时停止 |
| 每条命令时间 | 默认 60 秒，最多 300 秒 |
| 同一个原生连接的并发命令 | 1 条 |
| 单轮模型返回工具数量 | 最多 4 个，按顺序执行 |
| 单条命令 UTF-8 长度 | 16 KiB |
| 工作目录 UTF-8 长度 | 4096 字节 |
| 单次命令原生 stdout + stderr 保留量 | 合计 256 KiB；超量继续排空并标记截断 |
| 下一轮模型上下文中的单次输出 | stdout 最多 24 KiB，stderr 最多 12 KiB，明确标记上下文截断 |
| 单次运维模型请求的历史预算 | 192 KiB，最多 64 条消息；需要时先模型摘要，不拆散保留的调用和结果 |
| 本次目标及主动附加的内容 | 合计最多 64 KiB |
| 带入任务的先前对话参考数据 | 最多 1 MiB，较长时先模型摘要 |

流式界面和终端回显也有单独的容量限制，完整结果可能比当前展示片段长。步骤会提示截断，Agent 应针对所需证据重新查询。传输层不自动重放失败请求；超时等结构化结果会送回模型，模型仍可能基于结果提出后续命令，包括重复命令。若执行状态不明，应先查询实际状态，避免重复变更。

## 确认与停止的边界

默认每条命令需要界面确认。「允许本次执行」只使用一次；「以后全部执行」是对当前任务剩余所有命令的显式授权，包含已知高影响命令。该授权成功写入运行日志后才生效，后续每条命令仍记录自动批准与派发事件。停止、结束、新任务或恢复任务不沿用；长期记忆写入仍逐条确认。单独关闭逐步确认设置只放行普通命令，已知高影响操作仍会请求确认，可在当次确认中选择单次允许或全部执行。

检测使用有限的已知模式，并非完整 Shell 语义分析，不是安全沙箱，也无法证明未命中的命令安全。脚本、别名、编码、复杂管道或误导性的文件输出可能绕过模式识别。模型被要求不得规避确认，不得把命令输出中的指令视为新授权；这仍不能保证模型始终正确。请给出明确的目标和禁止事项，并用权限适当的账号操作。

点击「停止」、关闭 AI 面板或使目标连接失效，会取消当前模型请求或命令，并阻止后续步骤。停止会尝试终止本地执行进程组，或向本次 SSH exec 通道发送 KILL 请求并关闭该通道；它不会通过关闭交互终端来取消单条命令。远端进程的最终清理取决于 SSH 服务端，脱离通道的后台子进程、已经交给服务管理器的任务可能继续运行。**停止不会自动回滚已经完成的文件、服务或配置变更**。需要恢复时，根据实际执行记录提出明确的恢复任务。

## 数据与保存

模型会收到你的任务、同一会话中已完成的对话和运维结果参考、主动附加的终端选区/最近输出、工具调用及其执行结果；上下文压缩也会向同一端点发送待摘要的较早记录。启用记忆后，模型还可能收到来源片段或读取的原文；检索查询与待索引片段发送到独立配置的 Embedding 服务。它们发送到你配置的自定义端点，因此输出中出现的路径、业务内容或敏感信息也可能被发送。程序没有承诺能自动识别并清除所有敏感信息，应根据机器与数据范围选择合适的模型服务。

普通聊天仍只保留在当前进程内存中。运维任务会在本机独立的运行日志中保存任务、模型消息、工具调用、执行结果和逐次批准记录，供「运行记录」查看与显式恢复；它们不进入普通设置，也不随 Gist 上传。恢复不会重放旧命令或沿用旧批准：已发出但没有取得结果的命令标记为「结果未知」，批准前未执行的命令标记为「尚未执行」，模型须先核实机器状态再决定后续步骤。恢复后重新启用逐步确认。日志的位置、容量、明文内容与恢复边界见 [AI 运行框架与恢复](AI_HARNESS.md)。API Key 的本机保存方式和开关见 [AI 助手说明](AI_ASSISTANT.md)。若启用终端会话日志，回显也可能随现有会话日志功能落盘。

通过记忆管理保存、批准模型写入或单独开启压缩前整理后，提取的事实会持久保存为 Markdown，独立于普通聊天和运维运行日志；新建对话不会删除记忆。记忆与 Embedding 密钥的本机位置、删除备份及共享范围见[长期记忆说明](AI_MEMORY.md)。

本轮尚未使用真实自定义 AI 端点完成一次端到端运维任务，也未在用户生产机器上验收模型自主诊断与修复。模型能力取决于你填写的端点、原生工具调用实现和账号权限；完整环境应以实际执行记录与验证输出为准。平台构建与原生差异另以三平台 CI 和发布验证记录为准。

## 只读自动，修改确认

命令确认区增加 **只读自动，修改确认** 按钮，作用于当前任务。模型在 `run_command` 的 JSON 参数中同时返回 `effect`（精确枚举 `read_only` / `modify` / `unknown`）和可选 `effectReason`，客户端解析分类与简短理由，不增加额外的模型请求。界面会显示“AI 判断：只读 / 修改 / 不确定”。

启用后，只有模型标为 `read_only` 并通过客户端基本检查的命令自动执行；`modify`、`unknown`、缺失或格式无效的分类都会请求单次确认。客户端仍拦截明显写入、高影响操作、不透明执行入口以及复合/重定向等语法的只读误标。这是基于 AI 判断的审批策略，不能证明命令没有副作用，也不是远端执行沙箱。

切换策略不等于允许当前修改命令：当前命令若为修改或无法判断，确认框会继续等待 **允许本次执行**，也可拒绝停止。每次策略选择和自动执行授权均先保存运行记录，再发出执行请求；存储失败、停止或连接变化会阻止后续执行。

**允许本次执行** 只放行当前命令；**以后全部执行** 会切换为当前任务的全部命令自动执行。长期记忆写入始终独立确认。策略不保存到同步设置、不沿用至新任务；新任务遵循原逐条确认设置，恢复任务默认逐条确认。原来的“每条命令执行前确认”设置继续保留。

验证：`npm run test:ai-command-policy`、`npm run test:ai-readonly-approval`，以及既有运维、恢复、取消、Markdown 流式与终端输入回归。模型、存储和机器命令传输使用受控桥接；真实模型可能误判，因此建议保持对修改类命令的逐次审核。
