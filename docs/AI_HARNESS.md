# AI 运维运行框架

本版参考 [DeepSeek Harness 架构](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md) 的插件服务、追加事件及恢复机制，自行实现适合终端运维的轻量运行框架。继续使用 Tauri、Rust 和现有前端，不需要额外安装 Node 或运行 Cordis。现有自定义模型地址、API Key 系统凭据、SSH/本地命令、上下文压缩和独立 Embedding 记忆配置继续使用。

## 使用运行记录

1. 在右侧 AI 助手选择“运维”，选中已连接的 SSH 或本地终端后运行任务。
2. 点击 AI 顶部“运行记录”，查看本机最近的任务、机器、命令、输出及结论。普通聊天仍仅在本次运行中保留。
3. 恢复中断任务时，先连接原机器，再选择记录并点击“在当前连接继续”。连接身份不匹配时按钮不可用。已完成任务只能查看；需要新工作时新建任务。
4. 恢复后的新命令逐条确认。旧的允许执行决定不会沿用，也不会把以前的命令直接重新发送。

升级前没有持久运行日志的任务无法凭空恢复；运行记录从本版新建的运维任务开始。

## 恢复中的未知结果

“已派发，结果未知”表示应用可能在命令已经执行后中断。收到这个标记不能推断失败，例如重启服务可能已经完成。恢复会补充 `TOOL_OUTCOME_UNKNOWN` 观察，要求模型先查询实际状态。“尚未执行”补充 `TOOL_NOT_STARTED`，同样不自动重放该调用。已保存的完整结果保持原样，工具调用编号不会在恢复后重复使用。

这个区分参考官方 [Session 恢复说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/core/session/README.md)。本应用还要求派发记录成功落盘后才调用现有原生命令通道；结果落盘失败时停止继续规划，并保留不确定性。

## 插件与事件

`src/ai-harness.js` 提供服务注册、依赖排序、串行扩展事件、作用域清理、装载失败回滚和运行占用。内置 profile 在 `src/ai-agent.js` 组合八个插件：

| 插件 | 职责 |
| --- | --- |
| session | 原生 JSONL 日志、序号确认、读取与历史投影 |
| model | 自定义 Chat Completions 兼容模型请求 |
| tools | 固定工具参数验证与顺序执行 |
| policy | 单条命令确认和已知高影响操作确认 |
| context | 上下文占用估算与完整调用分组压缩 |
| memory | 当前机器/全局记忆与原有 Embedding 检索 |
| view | 面向界面的状态、命令和输出事件 |
| loop | turn/step 驱动，读取日志投影后进行下一次决策 |

运行中的插件不能被卸载或替换；任务结束后先释放运行占用，再撤销服务和监听器。拒绝或异常会停止执行，后续事件处理器不能撤销此前的拒绝。插件组合目前由应用内置代码声明，没有第三方插件下载或安装入口。

一次 step 包含模型请求和该次工具调用；一个 turn 可包含多个 step。主循环的系统/用户上下文、助手消息、调用、派发、确认、结果及结束状态保存为追加事件。每次下一步模型请求从这些事件投影出上下文，压缩写入新的历史投影事件，原事件不被删除。界面流式增量是临时事件，最终完整工具结果才作为持久观察。

这是一套参考实现，未接入官方 DSH SDK，也不提供官方插件协议兼容性。执行循环仍采用模型观察结果后继续调用工具的方式；未新增子 Agent 调度、独立反思评审器、自动故障重试或任意插件市场。模型适配仍为现有 Chat Completions 工具协议，没有自动新增特定模型的思考字段协议。

## 本机存储和边界

记录位于应用配置目录下的 `ai-runs/`，不会进入 Gist 配置同步。API Key 继续保存在系统凭据库，不作为运行日志配置字段；日志边界移除敏感字段，并对内容中已知密钥进行脱敏。命令、任务文字与输出仍可能包含机器或业务信息；日志不是所有未知秘密的自动识别器。

Unix 目录/文件权限为 0700/0600，拒绝符号链接、硬链接和特殊文件。每次追加核对连续序号、写入并同步落盘后确认；Unix 文件锁和 Windows 独占文件共享防止同时覆写同一日志。最后一条未写完整的崩溃残片可以在下一次合法追加时截除，完整损坏行不会自动修复。损坏或暂不可读的记录单独显示，其他合法记录仍可查看。Windows 的普通日志文件仍强制同步并上报错误；目录项没有可移植的目录同步保证，因此不承诺新建日志目录项在突然断电后一定存在。

每个会话最多 16 MiB、4096 个事件，最多 256 个会话，列表显示最近 100 个。接近容量上限时拒绝新的工具派发，并预留结果和结束记录空间。达到上限后任务明确停止，需要保留原记录、归档旧文件或缩小任务后另开任务，不会静默删减证据。本版尚无图形化归档管理。

追加时会在后台线程校验整个有界日志，单次 O(n)、累计多次追加可达 O(n²)；本版不保证无限运行或常数时间存储。恢复也需要用户重新建立真实连接，不会重用失效的 SSH 会话编号、自动连接其他机器或重新执行旧命令。

## 验证方式

`test:ai-harness` 验证真实插件内核、日志桥、消息投影和恢复语义；`test:ai-harness-agent` 使用真实 Agent/内核和受控原生桥验证保存失败、防重放、新确认及错目标；`test:ai-harness-ui` 验证记录界面的异步目标和凭据边界。既有运维、终端、上下文与记忆集成测试继续保留。

Rust `harness_log::tests` 使用真实临时文件验证重开读取、序号竞争、截断尾、损坏隔离、容量预留、权限及文件锁。原生模块独立测试不代替完整 Tauri 三平台编译；受控 UI、模型响应与命令桥测试不等于真实模型或生产机器运维验收。
