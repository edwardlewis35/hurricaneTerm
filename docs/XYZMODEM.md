# 终端文件传输与统一队列

工具栏的“传输队列”（Ctrl/Cmd+4）统一显示 SFTP 与 X/Y/ZMODEM 任务。再次点击工具栏按钮可关闭；关闭窗口不会取消传输。列表可筛选进行中、已完成和失败，显示机器、协议、方向、字节、速度与详细错误。任务与路径只在本次运行中保留，不会随 Gist 配置同步，也不会在重启后自动重放。

## X/Y/ZMODEM

这三种协议通过当前终端通道收发文件，不使用 SFTP。

1. 连接目标并选中终端。在对端启动对应收发程序：本机发送时对端接收（例如 `rz`），本机接收时对端发送（例如 `sz file`）；X/YMODEM 的对端需要相应协议参数或设备菜单。
2. 打开“传输队列 → 新建 X/Y/ZMODEM 传输”，检查显示的目标，选择协议和方向。
3. 浏览本机文件或输入路径。XMODEM 单文件；Y/ZMODEM 可一次发送多个文件。XMODEM 接收需要指定完整目标文件名，Y/ZMODEM 接收选择目录。
4. 选择同名处理，加入队列。同一终端的任务顺序执行；不同终端可独立传输。可取消与显式重试，重试需要对端重新进入相应收发状态。

传输在入队时绑定原连接、机器与连接代次，切换标签不会改目标。断线或重新连接会结束旧任务，不自动把旧传输交给新连接。传输期间普通键盘输入、同步输入和此连接的运维命令被原生层阻止，结束后恢复。当前手动启动传输，不自动识别终端里的 `rz/sz` 请求，也不自动输入远端命令。

X/YMODEM 支持 CRC16、校验和、128B/1KiB 数据块、超时和有限重传。XMODEM 不提供准确文件大小，接收默认保留末尾填充以免损坏二进制；确定文本使用 0x1A 填充时才勾选去除。YMODEM 使用标准文件名/大小头和批次结束帧。ZMODEM 使用内置 zmodem2 0.5.0 状态机，程序自身不依赖本机安装 lrzsz；对端仍需支持 ZMODEM。协议失败会明确结束，不伪造成功。

本版每个文件最多 4GiB−1 字节、每批最多128个文件，内存不随文件大小增长。接收拒绝路径穿越、控制字符和非法名称，先写同目录临时文件，再按“保留两份/跳过/覆盖”提交；失败清除未提交文件。已提交文件不会因取消后续文件而撤销。默认保留两份；“跳过”仍需接收并校验该文件的数据，完成后保留原文件。ZMODEM 发送支持对端的位置请求，本版接收不复用旧文件或跨任务断点状态。

SSH、原始 TCP、Unix 本地 PTY 和串口支持原始字节通道。Telnet 尚未实现二进制选项协商，本地 Windows ConPTY 不能保证任意字节保真，因此这些通道明确禁用；Windows 的 SSH/TCP 不受此限制。串口沿用现有 Unix 支持范围。

## SFTP

原文件管理下方队列保留，并与统一队列控制相同的任务。暂停、继续、取消、失败重试均作用于原生任务；关闭文件管理后仍更新进度。同一失败任务重试保留一行记录并生成新的原生传输编号。默认并发4，文件管理设置可调整。

## 依赖与验证

ZMODEM 上游为 [zmodem2](https://codeberg.org/jarkko/zmodem2)，许可证 MIT OR Apache-2.0，完整来源和一处空文件状态修复保留于 `src-tauri/vendor/zmodem2/HURRICANETERM_PATCH.md`。没有引入远端命令执行、自动打开文件等协议扩展。

回归包含生产前端控制器、SFTP/统一队列联动，原生字节独占/取消/溢出保护，三协议二进制与空文件批次，以及 Linux 下与独立 lrzsz 的双向真实文件互通。前端模拟 IPC 不代表原生端到端；协议互通也不替代真实串口硬件或原生桌面 GUI 验收。
